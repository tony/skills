# Prose rules

Apply to every piece of human-facing text a skill writes: reports, PR and
issue bodies, commit messages, changelog entries, tickets, chat summaries.
Quoted material, code, logs, and fixed output templates are exempt.

## Contents

- Cut these patterns
- Keep out of the record
- Formatting
- Check before sending

## Lead and density

- Lead with the result, then the support. A reader who stops after the first
  sentence still has the answer.
- Be concrete. A name, number, date, path, or mechanism beats an abstraction:
  "cut deploy time from 40 to 4 minutes", not "improved efficiency".
- Run the portability test: a sentence that could move unchanged to another
  project says nothing about this one. Cut it or replace it with a specific.
- Use active voice with a real subject, and direct verbs: "decided", not "made
  a decision"; "can", not "has the ability to".
- Repeat the right word. Rotating synonyms for one thing makes the reader ask
  whether they differ.
- Show, don't label. Delete lines that call a point important, subtle, or
  surprising; let the fact carry it.
- Never invent a claim, number, source, or example. When support is missing,
  say so or ask.

## Cut these words

Inflation: comprehensive, robust, seamless, production-ready, leverage, delve,
tapestry, best practices, gold-standard, first-class, world-class, cutting-edge,
paradigm shift, game changer, foster, utilize, facilitate, empower, streamline,
transformative, elevate, supercharge, harness, meticulous, paramount, realm.

Empty adverbs and phrases, unless they carry real uncertainty or contrast:
just, simply, actually, truly, fundamentally, importantly, crucially; "it's
worth noting", "it's important to note", "at the end of the day", "when it
comes to", "in order to", "going forward", "let's dive in".

## Cut these patterns

- Binary contrasts ("not X, it's Y", "it's not just X but Y"): state Y.
- Throat-clearing and faux-insight openers ("Here's the thing", "What most
  people miss"): state the point.
- Colon reveals ("The best part: it learns"): write a plain sentence.
- Trailing "-ing" analysis ("…, highlighting the team's commitment"): give the
  consequence or cut it.
- Importance puffery ("marks a pivotal moment", "plays a vital role"): state
  the fact.
- Reader-steering asides ("The key point is", "As you can see"): delete.
- Weasel attribution ("experts agree", "studies show"): name the source or cut.
- Negative listing, dramatic fragments, rhetorical setups ("What if I told
  you"), and stacked same-shape sentences.
- Fake-profound kickers and recap endings ("Ultimately…", "In conclusion…"):
  end on the last concrete point or the next action.

## Keep out of the record

- AI signatures: "Generated by", tool footers or trailers, "Certainly!",
  "Here is…", decorative emoji.
- Brittle references: line numbers, file or test counts, "as of" dates, bare
  SHAs, and local absolute paths, unless the text is evidence (a benchmark
  log, a stack trace, a release note).
- Diff narration: what moved, was renamed, or was removed, in text whose
  reader holds the result. The diff and the commit message carry history.
- Branch-internal history: intermediate states, abandoned approaches, and "no
  longer" behavior that no user of a published release experienced.
- Revision leakage: when re-checking earlier work, deliver the re-derived
  answer, not verdicts on the earlier one.
- Scaffolding: ownerless TODOs, speculation about future work, hedges and
  apologies.
- Coded labels: `[R1]`, `A1`, `Option B`. Write the plain imperative.

## Formatting

- Prose and nested sections over tables, unless the data is a real matrix.
- No headings over two-sentence sections; no bold sprinkled mid-sentence.
- Use bullets for parallel items, prose for an argument.
- Em dashes: none in short text, one or two in long text where a comma or
  period reads worse.
- One command per code block, with the explanation outside the fence.

## Check before sending

1. Does the first sentence carry the result?
2. Does every sentence pass the portability test?
3. Is any banned word, pattern, or record item above still present?
4. Is every number, name, and source real and checkable?
5. Would a sharp colleague read it aloud without wincing?
